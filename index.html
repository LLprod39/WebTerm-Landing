Self-hosted панель для серверов и SSH

WebTerm предназначен для администраторов и небольших DevOps-команд. В браузере доступны инвентарь серверов, SSH-терминал, файлы, мониторинг и журнал действий.

ИИ помнит контекст каждого сервера

Не как бесконечную переписку. WebTerm собирает проверяемые факты о сервере и передаёт нужную часть этой памяти в следующую задачу.

04 · повторение Кандидат в автоматизацию

Повторяемая успешная последовательность становится черновиком.

Автоматически

Замечает и подготавливает

  • сжимает историю в полезные факты, если включён worker памяти;
  • при включённом «Дежурном» сообщает о критическом алерте и помогает начать разбор;
  • ищет повторяемые безопасные действия и готовит черновик Skill или план Playbook.
проверка→
После подтверждения

Превращается в рабочий процесс

  • оператор проверяет команды, условия успеха и откат;
  • черновик сохраняется как Skill или оформляется в Playbook;
  • изменяющий запуск проходит правила доступа и явное подтверждение.

Главное: одна ошибка сама по себе не становится автоматизацией. Нужны повторяемость, успешные измеренные запуски и безопасная проверка результата. WebTerm может предложить действие, но не должен молча менять сервер.

Self-hosted не означает «без исходящего трафика»

Облачный LLM, MCP или уведомления создают внешний маршрут. Он появляется только после настройки, но его нужно учитывать в модели данных.

Что работает в v0.2.1

Статусы ниже относятся к профилю выпуска для одного внутреннего пилотного контура.

A
Основные функции
Инвентарь серверов, SSH-терминал, SFTP и редактор, мониторинг, проекты и участники, сессии, управляемые секреты и аудит.
B
Preview
Playbooks, AI-агенты, операторский чат, Studio pipelines и MCP-интеграции. Они включаются отдельно, могут меняться и пока не поддерживаются как основные функции.
C
Отключено
Плагины, Kubernetes Ops и MARS закрыты в рабочем профиле. Наличие экранов и кода не означает готовность к включению.
D
Развёртывание
Поддерживаемая конфигурация — один Linux-хост с Docker Compose. Отказоустойчивый кластер и публичный SaaS требуют другой архитектуры и отдельной проверки.
E
Стек
Django + Channels · React/Vite/TypeScript · PostgreSQL · Redis · Celery · Docker Compose · nginx. MCP, LLM-провайдеры и уведомления подключаются по необходимости.

Кому подходит

Небольшой DevOps/SRE-команде или администраторам, которые работают с собственными Linux-серверами.

Что подготовить

Отдельный хост, DNS или IP, TLS, ключ шифрования, резервные копии и список доверенных SSH fingerprints.

AI не обязателен

Инвентарь, терминал, файлы и мониторинг работают без LLM. Провайдер подключается только для AI-сценариев.

Кому пока не подходит

Публичному SaaS, HA-инсталляциям и командам, которым нужно рабочее администрирование Kubernetes из WebTerm.

Пока без утверждённого этапа: MARS, публичный SaaS и HA-кластер WebTerm. Windows endpoint management также остаётся кандидатом, а не начатой реализацией.

// 07 установка

Установка на отдельный Linux-хост

Репозиторий github.com/LLprod39/WebTerm · вместо YOUR_HOST — IP или DNS

install-server.sh ставит Docker при необходимости, клонирует репозиторий, готовит окружение и создаёт учётную запись администратора.

bash 
curl -fsSL https://raw.githubusercontent.com/LLprod39/WebTerm/v0.2.1/install-server.sh -o install-server.sh
chmod +x install-server.sh
./install-server.sh --repo https://github.com/LLprod39/WebTerm.git --branch v0.2.1 --dir /opt/webterm --host YOUR_HOST

пример: --host 10.0.0.15 · https: --https

Полный стек локально — для теста или лабораторного стенда.

bash 
git clone https://github.com/LLprod39/WebTerm.git
cd WebTerm
cp .env.example .env
docker compose up -d --build

health: curl http://127.0.0.1:8080/api/health/

Backend и frontend раздельно — вариант для разработки.

backend 
git clone https://github.com/LLprod39/WebTerm.git && cd WebTerm
python3.11 -m venv .venv-wsl && source .venv-wsl/bin/activate
python -m pip install --require-hashes -r requirements-dev.lock
python manage.py migrate && python manage.py createsuperuser
python manage.py runserver 0.0.0.0:9000
frontend 
cd frontend && npm ci && npm run dev

Версия рассчитана на внутренний пилот с именованными операторами и одним Linux-хостом. Это не заявление о готовности к публичному production, high availability или multi-tenant SaaS.

Сначала подключите тестовый сервер. Проверьте TLS, резервное копирование, права проекта, SSH fingerprints и аудит, а затем решайте, какие рабочие хосты добавлять.
